# 定义需求

先用一件具体工作定义需求，再推导页面与模块。普通用户描述业务目标和反馈；Agent 根据已有信息整理对象、流程及验收，不要求用户先设计模块树、组件或接口。给需求分配稳定编号，区分本轮、后续及待验证项。只集中询问影响实现的缺项；不重复询问用户已经明确的要求。

需求基线至少回答以下问题：

| 需求 | 要明确的内容 |
| --- | --- |
| 谁完成什么工作 | 目标用户、业务问题、本次工作的完成标准 |
| 用户处理什么对象 | 对象名称与关系，处理一次还是长期管理多条记录，如何创建、查找和重新打开，能否独立于 QuantDSH 项目使用 |
| 工作如何推进 | 每个阶段的状态、允许动作、下一步；无数据、异常和失败时如何继续 |
| 输入与成果在哪里 | 数据来源和固定版本，人工改动的范围，保存、重新打开和旧成果追溯 |
| AI 参与哪项工作 | 目标对象、必要输入、允许操作、结果落点，以及人如何查看、修改、采用或放弃 |
| 首轮做到什么 | 明确首轮范围、首页与列表/详情结构、导航返回和可复核样例，业务流程与真实 AI 协作分别验收 |
| 后续怎样调整 | 同一插件的需求与源码基线、用户反馈及保留范围；业务内容变化与源码迭代分别处理 |

例如一次“10 月 A 产线质量分析”：选择检验表版本，核对不可用于统计的记录，生成固定分析，再形成报告。人工填写核对决定和采用 Agent 核对建议都回到本次记录；重新分析保留旧运行；报告保存后可以从该记录重新打开。尚无可编辑报告或建议写回接口时，将相应行为列为待实现，不用只读 AI 文档或保存回执代替。

保存可版本化的 WORKBENCH_REQUIREMENTS.md，并通过已交付的开发服务保存相应需求修订。企业接口、真实字段和业务阈值未提供时标为待验证，不将示例当成生产配置。

质量分析初始范围可包含完整 CSV/XLSX 输入、字段映射、校验与清洗、检验合格率、缺陷分布与趋势、可复算报告及可选 AI 解读。明确分母、复检与去重、单位、时间范围及零样本规则；预览数据不能作为完整统计输入。

## 工作台复用 Office 的开发要求

工作台处理 Excel、CSV、Word、PPT 等文件时，优先使用 QuantDSH 已有 Office 插件及官方文件入口。文件预览、电子表格网格、单元格编辑、工作副本保存和支持格式的导出由 Office 拥有；工作台只实现业务字段映射、质量规则、清洗决策、统计、异常定位和报告组织，不新增独立电子表格编辑器或重复文档管理。业务指标表、异常列表与字段映射表单仍可由工作台展示。

开发前读取实际 Office 能力及版本，区分只读 CSV 预览、已有 XLSX 文件编辑与 Excel 工作副本接口，不能将某一路径支持的功能推定为全部支持。通过公开服务、明确资产/文档 ID 与修订关联；缺少公开接口时先在 Office 所有者中补充共享契约，并验收授权、生命周期、保存及导出，再接入工作台，不直接调用 Office 私有模块。

统计必须使用经过授权的完整数据，而不是 Office 预览的截断行列。开始分析时固定完整源文件或已保存工作副本的修订、内容摘要、工作表和区域，形成不可变分析快照；修改后重新保存并生成新运行，不改写历史结果。保留必要的后台完整解析与确定性计算，复用共享解析能力；Office 预览或编辑失败不得被当作成功导入。

验收必须覆盖：由工作台打开实际文件的 Office 入口；编辑并保存后分析使用新修订；历史运行仍引用旧快照；预览截断不影响完整统计；未授权、Office 未安装或能力不足时明确提示，不生成虚假成功或临时自制编辑器；支持的导出得到可打开的真实文件。上述场景通过前不得宣称 Office 与工作台已经打通。

## 工作台作为多模块业务系统的要求（优先于单页原型描述）

每个工作台插件是一套可独立使用的小型业务系统，一个安装包对应一个稳定工作台身份。宿主侧栏只提供一个“工作台”列表入口，业务插件从列表打开，内部导航和页面由插件呈现。多个内部模块不生成多个插件，不复制或替换官方宿主、Loader、会话及平台资源管理。

首次制作先明确业务对象、关系、操作和状态流转、数据来源及成果；再据此定义模块、导航、页面、Host 服务与授权、存储修订、迁移和模块依赖。稳定模块及页面 ID 由开发方案维护，便于后续定位，不让普通用户承担技术建模。页面布局是系统设计的一部分，首轮验收以一件工作能持续完成为准。

质量分析的工作路径是：选择或创建分析记录 → 导入固定来源 → 核对问题 → 生成分析 → 加工并保存报告。总览、数据、核对、历史及报告可据此组织页面，规则与资源配置按需打开。页面数量、六模块导航或固定分栏不作为所有工作台的默认模板。各页面读取同一业务对象及相关版本，任务执行复用既有服务与原生运行能力。

局部调整由用户描述页面或区域、修改目标和保留项，可附截图；已有页面选择仅辅助定位。Agent 检查当前源码及依赖，在同一插件中修改，说明真实跨模块影响并验证受影响流程。普通用户无需选择组件或操作可视化编辑器。专业人员可离线开发复杂插件，继续使用相同身份及公共规范。

本版本不集成 Puck 或通用拖拽编辑器。简单工作台通过需求模板、提示词开发和多轮反馈调整；复杂工作台支持专业开发后导入。Excel 和文档编辑继续复用 Office。

验收以业务对象的持续工作为准：导入固定来源 → 定位并保存核对决定 → 生成分析 → 查看结果 → 保存并重新打开成果；重启后状态一致，旧成果保持旧依据。启用 AI 的场景另外验收委托目标、候选回流、人工采用与继续加工。模型回复完成、候选待采用、决定待复核、成果已保存分别呈现。样式修改不改变统计与历史，源码更新保留原对象及资料。原型、源码测试和实际安装各自报告验证范围，不把其中一项当作整体完成。
